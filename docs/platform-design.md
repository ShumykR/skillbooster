# SkillBooster: як виглядатиме платформа (мікс варіантів 2 і 3)

Правило відбору: якщо зовнішній ресурс глибокий і справді безкоштовний, ми його беремо. Власні завдання пишемо лише там, де безкоштовної якісної практики немає.

## Що бачить користувач

**1. Карта шляху.** Головна сторінка — це граф етапів (Python → БД → API → безпека → Docker/CI → хмара/IaC → Kubernetes → observability → системний дизайн → AI-бекенд). Кожен етап має статус: не розпочато / у процесі / зроблено. Зверху видно загальний прогрес, серію днів поспіль і «що робити сьогодні».

**2. Сторінка етапу.** Складається з чотирьох блоків:
- «Навіщо це на роботі» — 3–5 речень простою мовою.
- «Що треба знати» — чекліст понять, які можна відмічати.
- «Вивчити» — посилання на найкращі безкоштовні ресурси (див. free-resources.md), для кожного позначено рівень, час і чи є автоперевірка.
- «Довести практикою» — завдання: зовнішнє (Killercoda, PortSwigger, KodeKloud) або власне з автоперевіркою.

**3. Власні завдання з автоперевіркою.** Користувач форкає шаблонний репозиторій (на кшталт rustlings чи Exercism), пише код, робить push, і GitHub Actions запускає pytest та показує пройдено/не пройдено. Результат записується у прогрес. Приклади завдань, яких немає безкоштовно в інших місцях:
- async FastAPI: ендпоінт під навантаженням, connection pool, таймаути;
- кеш з Redis: cache-aside, інвалідація, захист від cache stampede;
- черга завдань: ідемпотентний воркер, retry з backoff, dead-letter;
- rate limiter та idempotency keys для платіжного ендпоінта;
- міграції Alembic без простою;
- оптимізація повільного запиту за EXPLAIN ANALYZE;
- Dockerfile: multi-stage збірка, розмір образу, non-root, healthcheck (перевіряє скрипт);
- Terraform: модуль, який проходить `terraform validate` і набір політик (conftest);
- GitHub Actions: пайплайн, який збирає, тестує й публікує образ;
- AI: RAG на pgvector з оцінкою якості на еталонному наборі, MCP-сервер з тестами, захист від prompt injection.

**4. Наскрізний проєкт.** Один проєкт, який росте разом з етапами: AI-бекенд (FastAPI + Postgres + pgvector + Redis + Docker → CI/CD → Terraform на AWS → Kubernetes → Grafana/OpenTelemetry). Після етапу приходить «вимога» (наприклад, «додай кеш», «захисти API»), і користувач розвиває свій репозиторій. Це одразу портфоліо.

## Техніка

- **Фронтенд:** статичний сайт (Astro або чистий HTML/JS), контент у Markdown/YAML у репозиторії. Хостинг на GitHub Pages або Cloudflare Pages — $0.
- **Прогрес:** на старті в localStorage браузера + експорт/імпорт JSON. Пізніше, за потреби, вхід через GitHub і база (Supabase free tier).
- **Автоперевірка:** шаблонні репозиторії з pytest + GitHub Actions. Працює без нашого сервера і безкоштовно (публічні репозиторії мають безлімітні хвилини Actions). Результат можна підтягувати на сайт через публічний API GitHub за бейджем або статусом workflow.
- **Власний сервер на старті не потрібен**, бо вся «виконувана» частина живе в GitHub Actions.
- **AI-підказки (опційно, пізніше):** кнопка «поясни просто» або «дай підказку без розв'язку» через API моделі. Це єдина статття витрат, і ми її вмикаємо лише коли захочемо.

## Етапи реалізації

1. **MVP (перша ітерація):** карта шляху + 10 сторінок етапів зі зовнішніми ресурсами та чеклістами + трекінг прогресу. Це інтерактивний артефакт, який ти можеш відкрити відразу.
2. **Власні завдання:** шаблонний репозиторій + 5–8 завдань з автоперевіркою (Python/FastAPI, Redis, SQL, Docker, CI).
3. **Наскрізний проєкт:** сценарій AI-бекенду з вимогами по етапах.
4. **Опційно:** вхід через GitHub, спільний прогрес, AI-підказки.

## Відкриті рішення

- Мова інтерфейсу й контенту: українська чи англійська (я пропоную українська для пояснень і англійська для термінів).
- Чи робити платформу лише для себе, чи публічною для інших (впливає на акаунти й хостинг прогресу).
- Скільки годин на тиждень ти готовий вчитися, від чого залежить темп етапів.
