# №145 · Безпечне завантаження файлів 🟡

**Ситуація.** Форма «завантаж аватар» приймає `shell.php`, або `evil.png`, усередині якого HTML зі скриптом, або `.htaccess`, що змінює налаштування сервера. Unrestricted Upload це CWE-434, **№12 у MITRE CWE Top 25**. Атаку відпрацюй на лабах [PortSwigger (file upload)](https://portswigger.net/web-security/file-upload).

**Що зробити** у `validate_upload` (порядок перевірок і причини відмов у докстрингу). Окремо від завдання №13 (воно про потокове завантаження й розмір), тут про **довіру до клієнтських даних**.

**Підказки (без розв'язку):**
- `Content-Type` із запиту й розширення це лише твердження клієнта; перевіряй **вміст** (magic bytes);
- allowlist (список дозволеного) завжди надійніший за denylist, але `shell.php.png` показує, чому обидва разом краще;
- ім'я файлу для збереження генеруй сам (UUID), а оригінальне зберігай у БД: це заодно закриває path traversal (завдання №144) і колізії імен;
- `Path(name).name` не знає про `\\` на Linux: прибирай обидва роздільники.

**Чого тести не покривають (подумай):**
- magic bytes не гарантують валідності файлу: поліглот може бути PNG і HTML водночас. Тому віддавай користувацькі файли з окремого домену або з `Content-Disposition: attachment` і `X-Content-Type-Options: nosniff`;
- перекодування зображень (Pillow) знищує вбудований payload і метадані (EXIF з GPS); для документів потрібен антивірус (ClamAV);
- на S3 завантажуй через presigned POST з умовами `content-length-range` і `Content-Type`.

**Перевірка:** `python check.py t145`. Лише стандартна бібліотека.
