# №23 · Індекси 🟡

**Ситуація.** Три запити роблять `SCAN` по таблицях на 40 тисяч рядків. Кожен індекс прискорює читання, але сповільнює запис, тому потрібен **мінімальний** набір.

**Що зробити** у `create_indexes`: не більше 3 індексів, і щоб
1. запит про замовлення користувача читав індекс **без окремого сортування** (`TEMP B-TREE`);
2. запит `status + created_at` робив `SEARCH` по індексу;
3. пошук за `lower(email)` теж використовував індекс (подумай, чому звичайний індекс на `email` тут не спрацює).

Функція має бути ідемпотентною (`IF NOT EXISTS`).

**Перевірка:** `python check.py t23`. У тесті є `EXPLAIN QUERY PLAN`, подивись, як він читається.

**Підказки:** порядок колонок у складеному індексі; індекси за виразом. У PostgreSQL це ті самі ідеї плюс `EXPLAIN (ANALYZE, BUFFERS)`.
