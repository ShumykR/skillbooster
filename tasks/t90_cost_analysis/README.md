# №90 · Керування витратами: budget alerts, теги, «чому рахунок виріс» 🟡

**Ситуація.** Прийшов рахунок AWS на 4000 $ замість 1500 $. У консолі Cost Explorer тисяча рядків, і ніхто не знає, чия це вина. Правильний порядок дій завжди той самий: подивитись *що* виросло (сервіс, тип використання), *чиє* це (тег команди) і *коли* (день, коли пішов стрибок). А ще, щоб не дізнаватись із рахунку, потрібні бюджетні сповіщення (в тому числі за *прогнозом*), обов'язкові теги й виявлення аномалій.

**Що зробити** у `solution.py` (на вигрузці витрат як списку рядків, без AWS):
1. `cost_diff`: порівняти два періоди за сервісом, акаунтом, типом використання чи тегом; на першому місці найбільший приріст;
2. `budget_alerts`: порогові сповіщення (50/80/100%) та сповіщення за *прогнозом* витрат до кінця місяця;
3. `daily_anomalies`: дні, коли витрати стрибнули відносно ковзного середнього;
4. `untagged_report`: яка частка рахунку без тега власника і які сервіси там найбільші.

Точні формули, округлення й порядок результатів у докстрингу файлу.

**Підказки (без розв'язку):**
- групування: `defaultdict(float)` за ключем; ключ `tag:team` береться з `row["tags"]`, а відсутній чи порожній тег це «(untagged)»;
- порівнюй *округлені* суми, і `delta` рахуй від них, інакше «0.01 + 0.01 - 0.67» дає зайві знаки;
- прогноз до кінця місяця: `spend / day * days_in_month`, але перші дні шумні (тест на `day >= 3`);
- в аномаліях ковзне середнє береться від *попередніх* днів, не включаючи поточний.

**Подумай (тести цього не покривають), і зроби руками:**
- у консолі: Billing → Cost Explorer (групуй за Service, потім за Usage type; вимкни «Show only untagged» тощо), Budgets (alert на ACTUAL і FORECASTED), Cost Anomaly Detection (безкоштовний сервіс AWS з ML-аномаліями й сповіщенням у SNS/Slack);
- обовʼязкові теги (`team`, `env`, `service`) вмикають у Billing → Cost allocation tags, і працюють вони лише *після* активації й лише на нові витрати; Tag Policies в Organizations (завдання №92) і SCP, що забороняє створення ресурсів без тега, роблять це правилом, а не проханням;
- типові джерела несподіваних рахунків: NAT Gateway (трафік через нього платний за ГБ, завдання №83), міжзонний трафік, незупинені dev-середовища, EBS-томи й снапшоти без власника, CloudWatch Logs без retention, S3 версії без lifecycle, Elastic IP без привʼязки;
- Savings Plans / Reserved Instances для стабільного навантаження, Spot для переривного; Graviton (ARM) часто дешевший за ~20% при тій самій продуктивності;
- FinOps це процес, а не інструмент: щотижневий огляд топ-5 змін, власник у кожного ресурсу, показник «вартість на одного клієнта/запит».
