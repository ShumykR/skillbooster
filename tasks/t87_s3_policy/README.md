# №87 · Аудит політики S3 🟡

**Ситуація.** Бакет із даними клієнтів став публічним через одну політику `"Principal": "*"`, і так витікали бази великих компаній. Політики IAM читати важко, тому їх перевіряють автоматично: IAM Access Analyzer, Checkov, Prowler, S3 Block Public Access (останній вмикай завжди, це страховка нарівні з політикою).

**Що зробити** у `analyze_bucket_policy` (правила в докстрингу): знайти публічний доступ без обмежень, зайві `s3:*` та відсутність обов'язкового TLS.

**Корисно знати:**
- ефективний доступ залежить від IAM-політик, ACL і Block Public Access разом, а не лише від bucket policy;
- `Principal: "*"` з умовою `aws:PrincipalOrgID` це доступ для всієї вашої організації, а не публічний;
- політика `Deny` без `aws:SecureTransport` не дозволяє читати по http, і це вимога більшості стандартів (CIS, PCI);
- принцип мінімальних прав: конкретні дії (`s3:GetObject`) і конкретні ресурси (`arn:.../prefix/*`).

**Перевірка:** `python check.py t87`. Лише JSON і Python, AWS не потрібен.

**Далі:** `aws s3api get-bucket-policy` на власному бакеті й прожени функцію на результаті (`json.loads(response["Policy"])`).
