# №80 · Semantic versioning і автоматичний changelog 🟡

**Ситуація.** Релізи робить людина вручну: придумує номер версії «на око», пише changelog з памʼяті і щоразу забуває щось згадати. У результаті `1.4.0` ламає API, бо ніхто не помітив breaking change, а в changelog немає половини виправлень. Інструменти типу [release-please](https://github.com/googleapis/release-please) чи semantic-release роблять це з історії комітів: вони потребують лише дисципліни в повідомленнях (Conventional Commits).

**Що зробити** у `solution.py` (без git, на списках повідомлень):
1. `parse_commit`: розібрати `type(scope)!: опис` і футер `BREAKING CHANGE:`;
2. `next_version`: вибрати наступну версію за найвищим рівнем змін (окремі правила для `0.x`);
3. `changelog`: зібрати markdown зі секціями Breaking / Features / Bug Fixes / Performance.

Точний формат і правила в докстрингу файлу.

**Підказки (без розв'язку):**
- один регулярний вираз із групами для першого рядка розбирає тип, scope, `!` і опис; футер шукається серед решти рядків *на початку рядка*;
- перетворення «найвищий рівень» зручно робити числами (0 ніщо, 1 patch, 2 minor, 3 major) і брати `max`;
- breaking зі `fix` чи `chore` теж підіймає major: тип не має значення, коли є `!` або футер;
- breaking-коміт `feat!` потрапляє в *дві* секції changelog.

**Подумай (тести цього не покривають):**
- чому `0.x.y` має інші правила («все може ламатись») і коли проєкт має вийти на `1.0.0`;
- pre-release (`1.3.0-rc.1`), build-метадані та порядок версій за semver (`1.0.0-rc.1 < 1.0.0`); як з цим поводиться `packaging.version`;
- squash-merge: у `main` потрапляє заголовок PR, а не окремі коміти, тож перевіряти формат треба на заголовку PR (action `amannn/action-semantic-pull-request`);
- release-please відкриває *PR* з оновленим changelog і версією, а не публікує сам: людина нажимає merge, і лише тоді створюється тег і реліз (це і є точка контролю);
- версія в коді: одне джерело правди (`pyproject.toml` або тег із `setuptools-scm`), а не три місця, які розходяться.

**Перевірка:** `python check.py t80`. Спершу тести червоні. Лише стандартна бібліотека (`re`).
