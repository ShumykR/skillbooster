# №58 · Захист від SSRF 🔴

**Ситуація.** Функція «завантажити аватар за посиланням» дозволяє серверу ходити за адресою, яку дав користувач. Через неї діставали IAM-ключі з `169.254.169.254` у реальних компаніях.

**Що зробити** у `validate_url` (вимоги у докстрингу): схеми, userinfo, порти, імена `localhost`, екзотичні записи IP (`2130706433`, `0x7f.1`, IPv6-mapped), перевірка **всіх** адрес після DNS-резолву.

**Перевірка:** `python check.py t58`. Резолвер у тестах підмінений, мережа не потрібна.

**Чого тест не покриває (подумай сам):**
- DNS rebinding між перевіркою та реальним запитом: в production підключайся саме до перевіреної IP-адреси;
- редіректи: перевіряй кожен `Location` заново або вимкни їх;
- у хмарі вмикай IMDSv2 і обмежуй вихідний трафік мережевими правилами.
