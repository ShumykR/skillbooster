# №27 · Optimistic locking 🟡

**Ситуація.** Дві людини редагують один запис. Друга зберігає поверх першої, і зміни першої зникають безслідно.

**Що зробити** у `update_title`:
- зміна можлива, лише якщо версія в базі збігається з `expected_version`; після зміни версія збільшується;
- інакше `StaleDataError`, а дані не змінюються;
- якщо запису немає, це `LookupError` (інша помилка, ніж «застаріло»);
- перевірка й запис мають бути **одним** SQL-запитом, бо «прочитав версію, потім записав» знову має гонку (тест запускає 10 потоків).

**Перевірка:** `python check.py t27`

**У веб-API:** версію віддають як `ETag`/поле `version`, а при конфлікті повертають `409 Conflict` або `412 Precondition Failed`.
