# №17 · Feature flags 🟡

**Ситуація.** Нову функцію не вмикають усім одразу: спершу 1% користувачів, потім 10%, 50%, 100%, а якщо щось пішло не так, вимикають без деплою. Головна складність у тому, що користувач не повинен «мигати» (то бачить функцію, то ні) між запитами та між серверами.

**Що зробити** у `is_enabled` (вимоги у докстрингу): детермінована, монотонна й рівномірна відсоткова роздача з `allow`/`deny` списками.

**Подумай:**
- чому `random.random() < 0.1` на кожен запит це поганий варіант;
- чому `hash(user_id)` у Python ламає стабільність між процесами (тест це перевіряє окремим процесом із різним `PYTHONHASHSEED`);
- у production використовують LaunchDarkly, Unleash, GrowthBook, Flagsmith або прості конфіги у БД; логіка «відра» (bucketing) у них саме така;
- старі прапорці треба видаляти: це технічний борг.

**Перевірка:** `python check.py t17`. Статистичні перевірки мають великий запас, тож чесне рішення не флейкає.
