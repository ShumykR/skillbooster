# №240 · Інтерпретатори в коді: виправ 🟡

**Ситуація.** У одному сервісі дані користувача потрапляють у п'ять інтерпретаторів: cookie сесії розбирається через `pickle`, конфіг через `yaml.load`, калькулятор звітів через `eval`, шаблон листа через `str.format`, а email перевіряє регулярний вираз із вкладеними квантифікаторами. Перший дає виконання коду (CWE-502), другий теж, третій (CWE-95) також, четвертий читає секрети з пам'яті процесу (CWE-1336, CWE-134), п'ятий вішає воркер одним рядком (CWE-1333). Усі п'ять працюють на чесних даних, тому звичайні тести їх не помічають.

**Що зробити:** у `solution.py` наївна вразлива реалізація. Перепиши п'ять функцій за правилами докстрингу (формат cookie, дозволені вузли AST, ліміти, правила плейсхолдерів, граматика email). Тести подають корпус payload'ів і перевіряють три речі: зловмисний код не виконався (маркер у `os.environ`), усі погані входи дають `ValueError`, чесні входи працюють як раніше. Небезпечні на DoS входи (`9**9**9`, ReDoS) тест запускає в окремому процесі з таймаутом, тому помилка не заморозить `pytest`.

**Підказки (без розв'язку):**
- підпис перевіряй **до** розбору payload, а сам формат вибери такий, щоб розбір не міг виконати код; чи достатньо підпису, якщо секрет витік?
- у YAML-бібліотеки є «безпечний» завантажувач, але він кидає власні винятки: хто їх перетворить на `ValueError`?
- `eval` з порожніми `__builtins__` не є пісочницею. Подумай, чому, і як обійти дерево виразів: що ти дозволяєш (білий список вузлів), а не що забороняєш;
- степінь, зсув і множення можуть виробити гігантське число за мить: де в обході дерева перевіряти розмір, до обчислення чи після?
- `string.Formatter().parse` розкладає шаблон на частини без виконання: що тобі потрібно перевірити в кожній частині?
- у регулярного виразу з `+` всередині `( ... )+` час росте експоненційно; два способи лікування: однозначна граматика (розділювачі, яких немає в алфавіті сегментів) і межа довжини **до** запуску.

**Подумай:**
- чому cookie сесії краще замінити випадковим id у Redis (завдання №160), а підписані токени лишити для коротких одноразових даних?
- чим `ast.literal_eval` відрізняється від вашого калькулятора і чому його теж не варто віддавати зовнішньому входу без лімітів?
- у production для шаблонів листів беруть Jinja2 `SandboxedEnvironment` або Mustache без логіки: які ризики лишаються (SSTI, XSS у HTML-листах)?
- regex-движок із гарантією лінійного часу (RE2, `google-re2`) проти ручної граматики: коли що обирати?
