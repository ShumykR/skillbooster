# №178 · Структурний чанкер 🟡

**Ситуація.** Чанкінг «по N слів» (№129) розрізає таблицю посередині рядка, функцію посередині тіла й відриває абзац від заголовка, під яким він стоїть. Пошук потім повертає шматок «| mac | brew |» без назви колонок або код без пояснення, а модель відповідає навмання. Структурний чанкер іде за будовою документа, дає кожному чанку контекст (назва документа й шлях заголовків) і стабільні id, щоб при зміні одного розділу не переіндексовувати все.

**Що зробити** у `solution.py` (точні правила в докстрингу): `chunk_markdown(text, doc_title, max_words)`, що повертає `parents` (секції) і `children` (чанки для пошуку):
- розбір Markdown на блоки: заголовки, fenced-код, таблиці, абзаци;
- шлях заголовків із пропуском рівнів, contextual prefix для embedding;
- жадібне пакування блоків у child-чанки з межею в словах, але таблиці, код і абзаци лишаються цілими;
- parent-child: пошук іде по малих чанках, а в промпт можна віддати цілу секцію;
- стабільні id на основі змісту, не позиції.

Умова в каталозі згадує також HTML; у цьому завданні лише Markdown.

**Підказки (без розв'язку):**
- блоки зручніше розпізнавати рядок за рядком станом («зараз усередині коду»), а не одним регулярним виразом на весь документ;
- що має завершити відкритий fenced-блок, і чому `# коментар` усередині нього не заголовок;
- шлях заголовків це стек: що з нього треба прибрати, коли зустрічається заголовок того самого або вищого рівня?
- id має змінюватись, коли змінився зміст чанка, і не змінюватись, коли змінилось лише сусідство. Що саме варто хешувати?
- два однакові абзаци під одним заголовком дадуть однаковий id: як зробити їх різними, не втративши стабільності?

**Подумай:**
- як вибрати `max_words` і чому parent-child дозволяє мати малі чанки для точного пошуку та великий контекст для відповіді;
- що дає contextual prefix (Anthropic «contextual retrieval») і чому його кладуть у текст для embedding, а не показують користувачу;
- як за списками id старого й нового індексу порахувати, що додати, видалити й лишити (переіндексація без повного перерахунку embeddings);
- що зробити з HTML, PDF і таблицями без `|` (завдання №174), і де в capstone (M3-M4) живе цей чанкер.
