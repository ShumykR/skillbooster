# №18 · Часові пояси та DST 🟡

**Ситуація.** Нагадування «щодня о 03:30» мовчки не спрацювало навесні (такого часу не існувало), а восени спрацювало двічі. Звіт «за добу» показав 23 години замість 24. Ці баги з'являються двічі на рік і ніколи не в тестах, якщо дати для них не вигадати.

**Що зробити** у `solution.py` (правила в докстрингу): безпечне перетворення локального часу в UTC із політикою для пропуску/дубля, зсув на календарні дні та на реальні години, межі локальної доби.

**Корисно знати:**
- у БД зберігай `timestamptz`/UTC, у API віддавай ISO 8601 зі зсувом (`Z` або `+03:00`);
- «через 24 години» і «завтра о цій самій годині» це різні речі двічі на рік;
- зсув поясу не те саме, що пояс: `+02:00` не знає про правила DST, потрібно ім'я з бази IANA (`Europe/Kyiv`);
- правила DST змінюються законами, тому регулярно оновлюй `tzdata`;
- у тестах «заморожуй» час, а межі DST додавай явними кейсами, як тут.

**Увага:** тести використовують правила 2026 року з бази tz: Київ переходить 29 березня й 25 жовтня, Нью-Йорк 8 березня й 1 листопада. Якщо пакет `tzdata` застарілий, оновіть його: `pip install -U tzdata`.

**Перевірка:** `python check.py t18`.
