# №53 · Throttling входу 🟡

**Ситуація.** Хтось перебирає паролі до акаунта зі швидкістю тисяч спроб за хвилину. argon2/bcrypt уповільнюють кожну перевірку, але без ліміту спроб це лише полегшує DoS.

**Що зробити** у класі `LoginThrottle` (поведінка у докстрингу): ліміт невдалих входів у ковзному вікні, тимчасове блокування, скидання після успіху. Годинник приходить ззовні, тому справжнього очікування в тестах немає.

**Подумай (тести цього не перевіряють):**
- ключ `username` дозволяє зловмиснику заблокувати чужий акаунт навмисно; ключ `ip` обходиться ботнетом. Як комбінувати?
- блокування з експоненційним зростанням (1 хв, 2, 4…) краще за фіксоване;
- відповідь «акаунт заблоковано» розкриває, що логін існує: чи варто повертати однакову відповідь?
- у production лічильники живуть у Redis, а не в памʼяті процесу (завдання №37).

**Перевірка:** `python check.py t53`.
