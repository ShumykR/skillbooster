# №83 · VPC з нуля: підмережі, NAT, security groups, route tables 🟡

**Ситуація.** Усе, що ти запускаєш в AWS, живе у VPC, і більшість «воно не підключається» та «чому база доступна з інтернету» зводяться до чотирьох речей: яка в підмережі таблиця маршрутів, чи є NAT, що дозволяє security group і чи є в інстанса публічна адреса. Ці правила прості, але комбінації підступні: NAT поставили в приватну підмережу і він нічого не дає; публічний IP є, а маршруту на IGW немає; SG відкрив порт БД для `0.0.0.0/0` «на хвилинку».

**Що зробити** у `solution.py`: модель VPC описана словником (формат у докстрингу). Реалізуй:
1. `subnet_kind`: public/private/isolated за маршрутом за замовчуванням;
2. `can_reach_internet` і `reachable_from_internet`: вихід назовні та доступ ззовні (потрібен *збіг* маршруту, IGW, публічної адреси та SG);
3. `can_connect`: інстанс до інстанса за SG (і ingress, і egress, джерело за іменем SG або за CIDR);
4. `audit_vpc`: 9 типових помилок (VPC001–VPC009).

Модель навмисно спрощена (без NACL, IPv6, peering), щоб правила було видно.

**Підказки (без розв'язку):**
- модуль `ipaddress` вміє `ip_network(..., strict=False)`, `subnet_of`, `overlaps` і `ip_address in network`: усе потрібне вже є;
- «публічна підмережа» це не властивість підмережі, а наслідок її таблиці маршрутів (маршрут `0.0.0.0/0 → igw`); публічний IP без такого маршруту не працює;
- правило SG з джерелом `sg:X` означає «інстанси, у яких є SG X», тобто це посилання на групу, а не на адресу: так будують ланцюги ALB → app → db без жодних IP;
- security group має стан (stateful): відповідь на дозволений вхідний запит повертається без окремого правила; це тут не моделюється, але саме тому вистачає ingress призначення й egress джерела.

**Подумай (тести цього не покривають), і зроби руками:**
- Terraform: напиши цю саму мережу (`aws_vpc`, `aws_subnet`, `aws_internet_gateway`, `aws_nat_gateway`, `aws_route_table`, `aws_security_group`) і запусти `terraform plan`; потім `terraform validate` і аналізатор з завдання №84;
- NAT-шлюз коштує грошей щодня і за кожен ГБ: один на AZ для відмовостійкості (VPC004) проти одного на всіх для економії в dev; VPC endpoints (gateway для S3 і DynamoDB безкоштовні) прибирають трафік через NAT;
- NACL (stateless, на рівні підмережі) проти SG (stateful, на рівні інстанса): навіщо обидва шари і чому NACL рідко чіпають;
- Reachability Analyzer в AWS робить те саме, що `can_connect`, на справжній мережі: перевір ним свою схему;
- плануй CIDR наперед: перекриття з іншим VPC чи on-prem унеможливлює peering/VPN (VPC002 для різних VPC).
