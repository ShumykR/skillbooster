# №19 · Гроші 🟡

**Ситуація.** `0.1 + 0.2 != 0.3`, а `round(2.675, 2)` дає `2.67`. На рахунку 100 грн, ділимо чек на трьох: у кожного по 33.33, і одна копійка десь зникла. У фінансах такі «копійчані розбіжності» складаються в суди й невдалі аудити.

**Що зробити** у чотирьох функціях (точні правила у докстрингу): розбір суми з тексту, конвертація за курсом, ПДВ і справедливий розподіл суми між частинами без втрати копійки.

**Подумай:**
- у БД гроші зберігають як `NUMERIC(12,2)` або як ціле число копійок, не як `FLOAT`;
- у JSON суми передають рядками (`"12.30"`), бо JS-число теж float;
- для мультивалютності ще потрібен код валюти і її кількість знаків (JPY без копійок, KWD з трьома);
- прочитай, чому в Python `Decimal` за замовчуванням використовує `ROUND_HALF_EVEN`.
