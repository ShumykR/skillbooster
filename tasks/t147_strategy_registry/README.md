# №147 · Strategy: правила як функції + реєстр 🟢

**Ситуація.** Знижки в магазині ростуть як гриб: `if promo == "black_friday": ... elif promo == "vip": ...`. Кожна нова акція це правка центральної функції, а отже ризик зламати старі. **Strategy** виносить варіативну частину в окремі взаємозамінні «стратегії»; у Python стратегія це просто функція, а не клас з одним методом.

**Що зробити** у `solution.py` (правила в докстрингу): `StrategyRegistry` (реєстрація декоратором, послідовне застосування правил до поточної суми) і три фабрики правил `percent_off`, `fixed_off`, `capped`. Сума в копійках (`int`), як у завданні №19.

**Підказки (без розв'язку):**
- декоратор `register(name)` повертає функцію без змін, тож її можна викликати й напряму;
- фабрики повертають замикання; параметри фабрики перевіряй одразу при створенні правила, а не при першому виклику;
- порядок правил має значення: «−10% і потім −5 грн» ≠ «−5 грн і потім −10%»;
- перевірка всіх імен *до* запуску першого правила гарантує, що помилка в запиті не залишить побічних ефектів.

**Подумай:**
- коли достатньо `dict[str, Callable]`, а коли стратегії треба зробити класами (мають власний стан, кілька методів, `Protocol`);
- як цей реєстр зв'язаний з `if/elif`-ланцюжком: чому відкритість до розширення (Open/Closed) тут працює без правок рушія;
- звідки стратегії беруть дані про замовлення: через `ctx`, а не через глобальний стан.
