# №71 · Перевірка docker compose 🟡

**Ситуація.** `docker compose up` стартує застосунок раніше за Postgres, той падає з «connection refused», а ви лікуєте це `sleep 10`. До того ж пароль БД лежить у YAML у git, а порт Postgres відкритий на весь світ.

**Що зробити** у `check_compose` (правила у докстрингу): проаналізувати compose-файл і знайти ці проблеми. Ключова ідея: `depends_on` без `condition: service_healthy` чекає лише на *старт* контейнера, а не на готовність сервісу.

**Підказки (без розв'язку):**
- `depends_on` та `environment` мають по дві форми запису, обробити треба обидві;
- у `image` порт реєстру (`registry:5000/app`) не є тегом;
- сервіс може бути в `depends_on`, але відсутній у `services` (зламаний файл): не падай з винятком.

**Перевірка:** `python check.py t71`. Docker не потрібен, потрібен `pyyaml`.

**Далі:** запусти `docker compose config` на своєму файлі, а потім справжній `docker compose up` і подивись, як змінюється порядок старту після додавання `service_healthy`.
