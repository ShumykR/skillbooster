# №198 · Аналізатор lethal trifecta 🟡

**Ситуація.** Агент читає пошту, відкриває посилання з листів і вміє надсилати повідомлення. Кожна можливість окремо виглядає нешкідливо, але разом вони дають «lethal trifecta» (Simon Willison, 2025): приватні дані + недовірений вміст + канал назовні. Достатньо одного листа з прихованою інструкцією, і агент сам відправить вміст пошти зловмиснику. Фільтри промптів тут не рятують; працює лише структурне розведення можливостей по різних сесіях (агентах).

**Що зробити** у `solution.py` (формат конфігурації та точні правила в докстрингу): `analyze` знаходить небезпечні сесії, інструменти з усіма трьома можливостями одразу й пропонує, що саме прибрати; `plan_split` знаходить найменшу кількість сесій, щоб жодна не мала всіх трьох можливостей. Конфіг з опечаткою чи невідомим прапором має відхилятись, а не вважатись «безпечним».

**Підказки (без розв'язку):**
- сесія небезпечна через **набір** можливостей, а не через окремий інструмент: що рахувати для кожної сесії?
- інструмент, що сам має всі три прапори, не лікується розведенням по сесіях: чому він окремий тип знахідки і чому він враховується навіть поза сесіями?
- «прибрати найрідшу можливість» дає найдешевше виправлення: чому порядок при рівності має бути визначеним?
- для `plan_split` кожна сесія це «набір без однієї можливості»: скільки є способів вибрати такі сесії і чому перебору 7 варіантів достатньо?
- чому конфіг `{"exfiltraton": true}` (опечатка) має бути помилкою, а не мовчки ігноруватись (fail open)?

**Подумай:**
- що поза цим аналізатором теж дає канал назовні: Markdown-зображення з параметрами, DNS, коміти, «поділитись посиланням»? Як описати такі інструменти прапором?
- сесії розводять і за довірою до користувача: чим це відрізняється від human-in-the-loop підтвердження і CaMeL (завдання №197)?
- ціна розведення: два агенти без спільного контексту гірші за одного; коли це виправдано (звʼязок із №188 і з capstone M6)?
