# №22 · N+1 запит у SQLAlchemy 🟡

**Ситуація.** Ендпоінт «автори з книгами» на 20 авторів робить 21 запит до БД, а на 2000 робить 2001. Це найчастіша причина повільних списків.

**Що зробити** у `list_authors_with_book_titles`: вона повертає `{імʼя автора: [назви книг]}` і зараз ліниво підвантажує книги окремим запитом на кожного автора. Залиши результат тим самим, але щоб запитів було **не більше двох** незалежно від кількості авторів.

**Перевірка:** `python check.py t22` (тест рахує SQL-запити через подію `before_cursor_execute`).

**Підказки:** `selectinload` проти `joinedload`; у чому різниця й коли що краще. У реальному проєкті ввімкни `echo=True` і подивись на запити.
