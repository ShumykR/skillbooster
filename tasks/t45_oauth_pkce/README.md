# №45 · OAuth2 «Увійти через Google/GitHub»: authorization code + PKCE 🟡

**Ситуація.** Ти додаєш вхід через зовнішнього провайдера. Типові помилки в таких інтеграціях потрапляють у звіти про вразливості: відсутній `state` (CSRF на вході: атакувальник підсовує жертві *свій* код, і жертва заходить в акаунт атакувальника), код без PKCE (перехоплений `code` можна обміняти будь-кому), `id_token` без перевірки `aud`/`iss`/`nonce` (токен, виданий для іншого застосунку, приймається як свій).

**Що зробити** у `solution.py`: `code_challenge`, `new_verifier` і клас `OAuthClient` з методами `start` та `callback`. Усі кроки перевірок і їхній порядок у докстрингу файлу. Провайдер у тестах це мок, що сам перевіряє PKCE, `redirect_uri` та одноразовість коду, як справжній: помилку в `code_verifier` чи `redirect_uri` ти побачиш як відмову обміну.

**Підказки (без розв'язку):**
- PKCE S256: `BASE64URL(SHA256(verifier))` без `=`; перевір себе на векторі з RFC 7636, додаток B (він у тесті);
- `state` та `verifier` лежать у серверній сесії, не в cookie у відкритому вигляді і не в URL; `session.pop(...)` дає «одноразовість» безкоштовно;
- розгляд помилок: спочатку дістань і видали очікуваний стан із сесії, і вже потім перевіряй параметри: інакше невдала спроба залишає «живий» стан для повтору;
- `hmac.compare_digest` для порівняння `state`;
- `urllib.parse.urlencode` для побудови query.

**Подумай (тести цього не покривають):**
- чому PKCE потрібен навіть серверним застосункам, а не лише мобільним і SPA? Що дає `nonce` понад `state`?
- підпис `id_token`: тут його не перевіряємо, бо токен прийшов напряму з token endpoint по TLS. Коли перевірка за JWKS стає обов'язковою (токен прийшов від клієнта, implicit flow, `userinfo`)? Див. завдання №51;
- `redirect_uri` має збігатися з зареєстрованим *точно*; wildcard і частковий збіг це відомі вразливості (open redirect, див. №158);
- прив'язка акаунтів: що робити, якщо email з Google збігається з існуючим локальним акаунтом? Автоматичне злиття без підтвердження це захоплення акаунта (account takeover);
- зберігання `access_token`/`refresh_token`: шифрування у БД, мінімальні scopes, відкликання при виході.

**Перевірка:** `python check.py t45`. Спершу тести червоні. Лише стандартна бібліотека. Для практики на справжньому провайдері: GitHub OAuth App або Google Cloud OAuth client (безкоштовно), а в production бери перевірену бібліотеку (Authlib), а не власний код.
