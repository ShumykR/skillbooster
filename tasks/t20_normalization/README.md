# №20 · Нормалізація до 3NF 🟢

**Ситуація.** Є «плоска» таблиця замовлень: `order_id, customer_id, customer_email, product_id, product_name, qty`. Email клієнта повторюється в кожному рядку, змінити його в одному місці й забути в іншому це класична аномалія оновлення. Нормалізація розкладає таблицю так, щоб кожен факт зберігався один раз.

**Що зробити** у `solution.py`: реалізувати алгоритми теорії реляційних БД на функціональних залежностях: замикання, кандидатні ключі, перевірку 3NF, мінімальне покриття й синтез схеми (докстринг описує кожну функцію).

**Корисно знати:**
- 2NF прибирає залежність від *частини* складеного ключа, 3NF прибирає транзитивні залежності (`A → B → C`);
- BCNF суворіша за 3NF: у тестах є відношення, яке в 3NF, але не в BCNF (`AB → C`, `C → B`);
- у реальному проєкті денормалізацію роблять свідомо (читання, аналітика), але лише після нормалізації й вимірювань.

**Перевірка:** `python check.py t20`. Навчальне завдання: нічого, крім стандартної бібліотеки, не потрібно.
