# №5 · Валідація та контракти, версіонування API 🟡

**Ситуація.** Мобільний застосунок v1 надсилає `phone` рядком і не оновиться ще пів року. Новому вебклієнту потрібен телефон як структура (`country_code` + `number`). Якщо просто змінити модель, старі клієнти почнуть отримувати 422, і ти дізнаєшся про це зі скарг у сторах.

**Що зробити** у `solution.py` (`create_app`): два контракти над одним сховищем. Точні форми запитів, відповідей і правил валідації описані в докстрингу файлу:
- `/v1/users` терпима до зайвих полів, але перевіряє формат телефону (код країни з короткого списку `KNOWN_CODES`, бо «+380501234567» без довідника однозначно на код і номер не поділити); кожна відповідь має `Deprecation: true` і `Sunset`;
- `/v2/users` сувора: `extra="forbid"`, структурований телефон, жодних «м'яких» приведень типів;
- користувач, створений через одну версію, читається через іншу в її форматі.

**Підказки (без розв'язку):**
- у pydantic v2 `model_config = ConfigDict(extra="forbid", strict=True)` робить модель сувору, `extra="ignore"` (типове) терпиме;
- одна внутрішня модель (як зберігаємо), дві пари моделей запит/відповідь (як показуємо), і функції перетворення між ними: версії API не повинні дублювати бізнес-логіку;
- `APIRouter(prefix="/v1")` і `/v2` в одному застосунку; заголовки можна додати через параметр `Response` у ендпоінті або `dependencies` на роутері;
- `Annotated[str, StringConstraints(strip_whitespace=True, min_length=1, max_length=50)]` або `field_validator`.

**Подумай (тести цього не покривають):**
- версія в URL, у заголовку (`Accept: application/vnd.app.v2+json`) або в полі: що простіше кешувати, документувати, підтримувати в логах?
- «Tolerant reader» для клієнтів і «strict writer» для сервера (закон Постеля): де він працює, а де прихована проблема з безпекою (mass assignment, завдання №162)?
- коли можна вимикати v1? Які метрики це покажуть (частка запитів по версіях, по `User-Agent`)? Чому `Sunset` без моніторингу не працює?
- нові необов'язкові поля у відповіді це зворотно сумісна зміна, а перейменування чи видалення поля ні: контрактні тести старого клієнта ловлять саме це.

**Перевірка:** `python check.py t05`. Спершу тести червоні: старого ендпоінта `/v1/users` ще немає.
