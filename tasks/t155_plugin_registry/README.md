# №155 · Factory і автореєстрація через `__init_subclass__` 🟡

**Ситуація.** Експортер у CSV, JSON, XLSX: функція `create_exporter(fmt)` з ланцюжком `if/elif`, який треба правити при кожному новому форматі, і хтось завжди забуває. У Python клас може сам зареєструвати себе при оголошенні: `class Csv(Exporter, key="csv")`, і додавання формату це один новий клас, жодних правок «центру».

**Що зробити** у `Registered` (докстринг): `__init_subclass__`, що веде реєстр у корені ієрархії, плюс `create`, `get`, `keys`.

**Підказки (без розв'язку):**
- `__init_subclass__` викликається на *батьківському* класі при створенні кожного нащадка, ключові слова з `class X(Base, key=...)` приходять як аргументи;
- реєстр має бути своїм у кожного кореня (інакше `Exporter` і `Importer` перемішаються): подумай, де його створити;
- якщо викинути виняток у `__init_subclass__`, клас не створюється;
- не забудь передати решту аргументів у `super().__init_subclass__(**kwargs)`, інакше зламаєш міксини.

**Подумай:**
- реєстрація відбувається при *імпорті* модуля з класом, тому плагіни треба імпортувати (або знаходити через entry points: `importlib.metadata.entry_points`, так працюють плагіни pytest);
- глобальний реєстр ускладнює тести (стан живе між тестами), тому тут реєстр свій для кожної ієрархії;
- для простих випадків достатньо словника та декоратора (завдання №147); метаклас потрібен рідко.

**Перевірка:** `python check.py t155`. Лише стандартна бібліотека.
