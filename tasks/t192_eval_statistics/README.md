# №192 · Статистика evals 🟡

**Ситуація.** Новий промпт набрав 78% замість 74%. Це покращення чи шум? На 50 кейсах різниця в 4 п.п. це два кейси, і вона зникає при іншому seed моделі. Без статистики гейт у CI або падає на шумі (команда перестає йому вірити), або пропускає справжнє погіршення.

**Що зробити** у `solution.py` (точні формули та порядок дій у докстрингу): `bootstrap_ci` (довірчий інтервал для середнього), `paired_bootstrap` (парне порівняння двох версій на тих самих кейсах), `min_sample_size` (скільки кейсів потрібно для заданої похибки) і `regression_gate` (рішення «пропустити/заблокувати» з поясненням). Випадковість лише через `random.Random(seed)`, тому результати детерміновані.

**Підказки (без розв'язку):**
- парне порівняння працює з різницями по кейсах, а не з двома незалежними інтервалами: чому це вужче й точніше?
- процентильний bootstrap залежить від точного способу вибору індексів: тримайся формул докстрингу дослівно, інакше значення не збіжаться;
- на малому наборі інтервал широкий за визначенням: що має зробити гейт, коли кейсів менше за мінімум?
- «не гірше за базу» і «ніяк не змінилось» це різні гіпотези: з якого боку інтервалу гейт має дивитись на нуль і допуск?
- розмір набору зростає як 1/похибка²: який висновок з цього для бюджету на розмітку?
