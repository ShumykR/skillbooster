# №28 · Idempotency key для платежів 🟡

**Ситуація.** Клієнт не отримав відповідь через таймаут і повторив запит. Гроші списано двічі.

**Що зробити** у `solution.py` (там уже є наївна реалізація):
- без заголовка `Idempotency-Key` відповідати `400`;
- повторний запит з тим самим ключем і тим самим тілом повертає **ту саму** відповідь з заголовком `Idempotent-Replayed: true` і не створює нового списання;
- той самий ключ з іншим тілом дає `422`;
- паралельні повтори з одним ключем створюють **один** платіж (гонка!).

**Перевірка:** `python check.py t28`

**У production:** ключі зберігають у Redis/Postgres з TTL (наприклад, 24 години) і унікальним індексом. Тут достатньо памʼяті процесу, але логіка та сама.
