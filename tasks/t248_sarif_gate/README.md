# №248 · Security gate на SARIF 🟡

**Ситуація.** У CI працюють SAST, сканер секретів, IaC- і залежностевий сканери, і кожен пише власний звіт у форматі SARIF. Якщо блокувати збірку за будь-якою знахідкою, команда за тиждень вимкне gate; якщо не блокувати, вразливості просочуються. Робочий компроміс: старі знахідки (baseline) не блокують, нові вище порога блокують, а виняток живе недовго, має власника й причину. Тут ти пишеш ядро такого gate: злиття звітів зі стабільними відбитками і рішення pass/fail з поясненням.

**Що зробити** у `solution.py` (точні правила в докстрингу):
- `merge_sarif(docs)`: злити звіти SARIF 2.1.0 у список знахідок зі severity, нормалізованим шляхом і стабільним відбитком (`fingerprint`), що не залежить від номера рядка;
- `evaluate_gate(findings, baseline, waivers, policy, today)`: розкласти знахідки на ignored / baselined / waived / blocking, перевірити винятки (власник, причина, термін, максимальний горизонт) і повернути структуру з `passed` та поясненням.

**Підказки (без розв'язку):**
- номер рядка змінюється при кожному коміті вище за знахідку: що тоді має входити у відбиток, щоб baseline не «протікав»?
- два однакові порушення в одному файлі не повинні ховатися за baseline першого: як відрізнити їх, не використовуючи номер рядка?
- `security-severity` це числова оцінка (як CVSS), а `level` лише груба шкала: яка з двох точніша, і де шукати кожну?
- межі дат: що означає «діє до 21.10» у день 21.10? Задай це одним порівнянням і перевір обидві сторони межі;
- недійсний виняток не має мовчки зникати: хто в команді повинен про нього дізнатися?

**Подумай:**
- baseline це борг: як не дозволити йому рости (наприклад, окремий звіт «baselined за 30 днів») і чи варто блокувати нові знахідки низької severity в чутливих каталогах?
- чому винятки краще зберігати в репозиторії поруч із кодом (review, історія), а не в налаштуваннях сканера?
- SARIF у GitHub Code Scanning уже має dismissals і baseline: чим твій gate кращий чи гірший, і що з цього віддати платформі (capstone M7, security gates)?
- як би ти врахував EPSS чи reachability з №247 у порозі блокування?
