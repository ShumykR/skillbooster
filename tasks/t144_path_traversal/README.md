# №144 · Path traversal 🟡

**Ситуація.** `open(os.path.join(UPLOAD_DIR, filename))` з іменем від користувача. Запит `../../etc/passwd` (або `..%2f..%2f` у кодованому вигляді, який фреймворк розкодує за тебе) віддає системні файли. Path traversal це CWE-22, **№6 у MITRE CWE Top 25**; у OWASP Top 10:2025 він у категорії A01. Атаку відпрацюй на лабах [PortSwigger (path traversal)](https://portswigger.net/web-security/file-path-traversal).

**Що зробити** у `safe_join` (правила в докстрингу). Тести працюють на **справжній файловій системі** (`tmp_path`): створюють теку, файли, сусідню теку з таким самим префіксом і symlink.

**Підказки (без розв'язку):**
- `os.path.realpath` розкриває `..` і symlink; після цього порівнюй не рядки, а компоненти шляху (`os.path.commonpath`);
- `str.startswith(base)` дає хибнопозитив для `/data/uploads-evil`;
- не намагайся «вичистити» `../` заміною: `....//` перетвориться на `../`. Перевіряй **результат**, а не вхід;
- symlink створюється лише якщо ОС дозволяє (на Windows потрібні права); тест тоді автоматично пропускається.

**Чого тести не покривають (подумай):**
- TOCTOU: між перевіркою і відкриттям файл можуть підмінити; на Linux відкривай через `openat`/`O_NOFOLLOW`;
- найкращий захист це **не брати імена від користувача**: зберігай файли під UUID, а оригінальне ім'я тримай у БД (завдання №145);
- інші точки входу: розпакування архівів (zip slip), `send_file`, шаблонізатори, `open()` у фоновому воркері.

**Перевірка:** `python check.py t144`. Лише стандартна бібліотека.
