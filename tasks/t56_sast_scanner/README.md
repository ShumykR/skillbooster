# №56 · Свій мінімальний SAST 🟡

**Ситуація.** Код-рев'ю не помічає `shell=True` у 40-му файлі діффа. SAST (static application security testing) читає код без запуску й шукає небезпечні патерни: [bandit](https://bandit.readthedocs.io/) для Python, [semgrep](https://semgrep.dev/) для багатьох мов. DAST (наприклад, [OWASP ZAP](https://www.zaproxy.org/)) натомість атакує вже запущений застосунок.

**Що зробити** у `scan_python` (правила у докстрингу): обійти AST, розпізнати виклики попри перейменування імпортів і знайти небезпечні випадки без хибних спрацювань на рядки та коментарі.

**Підказки (без розв'язку):**
- `ast.walk` обходить усі вузли; нас цікавить `ast.Call`;
- імʼя виклику (`sp.run`, `run`) треба звести до повного (`subprocess.run`) за імпортами файлу;
- `shell=True` це ключовий аргумент (`ast.keyword`) зі сталим значенням `True`; `shell=flag` не доводиться статично, тут його ігноруємо;
- коментарі в AST не потрапляють, тож для `# nosec` треба зазирнути у вихідні рядки.

**Перевірка:** `python check.py t56`.

**Далі:** запусти справжній `bandit -r .` та `semgrep --config auto` на своєму проєкті й порівняй, що знайшли вони, а що твій сканер. Підключи один із них у CI.
