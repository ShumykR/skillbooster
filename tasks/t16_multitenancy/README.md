# №16 · Мультитенантність 🟡

**Ситуація.** B2B-сервіс зберігає дані всіх клієнтів в одній таблиці. Один забутий `WHERE tenant_id = ...` в одному ендпоінті, і клієнт A читає (або видаляє) дані клієнта B. Це реальний клас інцидентів, а не теорія.

**Що зробити** у `NoteRepo` (контракт у докстрингу): зібрати весь доступ до даних в одному місці, де `tenant_id` додається до кожного запиту.

**Подумай (тести цього не покривають):**
- у Postgres є **row-level security** (`CREATE POLICY ... USING (tenant_id = current_setting('app.tenant'))`): захист на рівні БД, коли помилку допустив розробник;
- `tenant_id` має братись із перевіреного токена, а не з тіла запиту;
- кеші, черги, S3-префікси та логи теж треба розділяти по tenant, а не тільки таблиці;
- альтернативи: схема на клієнта або БД на клієнта (дорожче, але ізольованіше).

**Перевірка:** `python check.py t16`. Використовується вбудований `sqlite3`.
