# №191 · Evals траєкторій агента 🔴

**Ситуація.** Агент підтримки відповів правильно, але по дорозі викликав `delete_db`, п'ять разів повторив той самий пошук і пропустив крок `verify`. Фінальний текст це не показує. А завтра той самий агент на тому самому запиті провалиться: LLM недетермінована, тому один успішний запуск майже нічого не доводить. Для агентів перевіряють **траєкторію** (які інструменти, в якому порядку, скільки кроків) і рахують **pass@k** (чи вміє взагалі) та **pass^k** (чи можна покладатись, як у τ-bench).

**Що зробити** у `solution.py` (точні правила й коди порушень у докстрингу):
- `evaluate_trajectory`: перевірка траєкторії за специфікацією (обов'язкові й заборонені інструменти, частковий порядок, ліміт викликів, повтори, успіх задачі);
- `pass_at_k`, `pass_hat_k`: оцінки за n запусків, з яких c успішних;
- `run_agent_eval`: n запусків кожної задачі, підсумок по задачах і середнє.

**Підказки (без розв'язку):**
- «частковий порядок» не вимагає, щоб `a` стояло безпосередньо перед `b`: що саме треба перевірити для *кожного* виклику `b`, і що робити, коли `a` немає зовсім?
- «однаковий виклик» залежить від аргументів; чи зміниться він, якщо ключі в `args` переставити місцями?
- у `pass@k` немає сенсу піднімати `c/n` до степеня `k`: запуски *беруться* з вибірки без повернення. Що тоді рахує комбінаторика, і чому формула не вимагає окремої гілки для «усі невдалі»?
- помилка самого агента (виняток, сміття замість траєкторії) не повинна зупиняти весь eval: як її порахувати?
- коди порушень повертаються відсортованими й без дублікатів: чому важлива стабільність порядку для порівняння прогонів у CI?

**Подумай:**
- чому для чат-бота зазвичай дивляться на pass@k, а для агента, що змінює дані клієнта, на pass^k? Яке `k` ви б поставили для операцій із грошима?
- траєкторія може бути «іншою, але правильною»: коли жорсткий порядок кроків шкодить (рефакторинг, пошук), а коли потрібен (спершу перевірка прав, потім дія)?
- які порушення мають блокувати merge безумовно (заборонений інструмент), а які лише знижувати оцінку (зайві виклики)? Зв'язок з бюджетами з №133 і дозволами інструментів з №137.
- n=5 запусків це дорого й шумно: як вибрати n і як звітувати довірчий інтервал (завдання №192)?
