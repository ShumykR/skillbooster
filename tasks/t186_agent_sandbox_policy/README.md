# №186 · Політика sandbox для агента 🔴

**Ситуація.** Coding-агент має право читати файли проєкту, ходити на кілька хостів і запускати `git status`. Один отруєний README пропонує йому «перевірити конфіг» через `../../.ssh/id_rsa`, `curl http://169.254.169.254/` чи `rm -rf`. Промпт «не роби цього» не захист: рішення приймає код, що стоїть між агентом і системою. Помилки класу path traversal (CWE-22), ін'єкції команд (CWE-78) та надмірних прав (CWE-250) тут стають правилами allow/ask/deny.

**Що зробити** у `solution.py` (точні правила в докстрингу): клас `Sandbox` з методом `decide(action)`. Дію він не виконує, лише вирішує: `allow`, `ask` (спитати людину) чи `deny`. Правила це glob-шаблони з пріоритетом `deny` понад `ask` понад `allow`, а файлові шляхи спершу канонізуються (`..`, symlink), і лише потім порівнюються з шаблонами. Окремо: мережа (включно з хитрими записами IP), процеси і ліміти ресурсів за життя sandbox. Тести працюють із справжніми теками та symlink у `tmp_path` (тести з symlink пропускаються, якщо система не дозволяє їх створити).

**Підказки (без розв'язку):**
- порівнювати треба не той рядок, який надіслала модель, а те, куди він справді веде: який інструмент стандартної бібліотеки розкриває symlink навіть для файлу, якого ще немає?
- чому перевірка «шлях починається з імені робочої теки» помиляється для сусідньої теки з таким самим префіксом?
- `deny` має діяти за будь-якого з двох поглядів на шлях (як написано і куди веде); а `allow` лише за одного: чому така асиметрія безпечна?
- для чутливості до регістру порівняй наслідки двох помилок: «заборонене пройшло» і «дозволене не пройшло»; який варіант fail closed для `deny`, а який для `allow`?
- IP-адресу можна записати десятковим числом, у вісімковому чи шістнадцятковому вигляді: який простий принцип відсікає всі «екзотичні» форми, не навчаючи парсер усіх форм?

**Подумай:**
- чому AST-перевірка згенерованого агентом Python-коду (заборона `import os`, `eval`, `open`) не є пісочницею: які обходи залишаються (`getattr`, `__subclasses__`, `importlib`, `ctypes`, мова самого shell у `subprocess`), і чому межу треба ставити на рівні ОС або контейнера, а не мови?
- TOCTOU: між `decide` і справжнім відкриттям файла хтось може підмінити symlink; як це закривають у production (`openat` з `O_NOFOLLOW`, відкриття з fd робочої теки, read-only mount, user namespaces)?
- де проходить межа між цією політикою і справжньою ізоляцією: контейнер без мережі, gVisor, Firecracker, E2B, окремий непривілейований користувач, seccomp? Яку з цих ланок вона не замінює?
- ліміт у `decide` рахує дії лише у цьому процесі. Як рахувати бюджет, коли агентів багато або процес перезапускається (завдання №133, №187)?

**Перевірка:** `python check.py t186`. Лише стандартна бібліотека. Далі: підключи `Sandbox` до свого агента перед викликом інструментів (завдання №137) і додай запис кожного `deny`/`ask` у журнал як сигнал атаки.
