# SkillBooster: контекст для Claude Code

Власник: Roman, junior Python-розробник (FastAPI, AWS), цікавиться DevOps. Мова спілкування: **українська**, технічні терміни англійською.

## Мета проєкту

Сучасний (2026) навчальний шлях для Python-бекендера + DevOps + безпеки + AI-інженерії та платформа з практичними завданнями. Пріоритет: архітектура, проєктування й насамперед безпека (AI пише дедалі більше коду, відповідальність лишається за розробником).
Початковий матеріал: транскрипт відео 2023 року про MERN-бекенд; ми адаптували його під Python і додали AI-стек (див. `docs/` та сторінку «Що змінилось з 2023» на сайті).

Принцип: де є глибокий безкоштовний зовнішній ресурс, посилаємось на нього; власні завдання пишемо лише там, де безкоштовної якісної практики немає.

## Як запускати

- Сайт: відкрити `index.html` або `python -m http.server 8000`.
- Завдання: `cd tasks && pip install -r requirements.txt && python check.py` (або `python check.py t02`). Потрібен Python 3.11+. `check.py` пише `skillbooster-sync.html` (JS-редирект на `index.html#/sync/t2,t6`: Windows губить `#` у file://-посиланнях) і `skillbooster-progress.json` (запасний імпорт, режим merge). `--open` відкриває сайт, `SKILLBOOSTER_URL` задає адресу сайту.
- Після зміни каталогу завдань чи `STAGES`: `python tools/gen_data.py`.

## Правила роботи над завданнями (важливо)

- Кожне нове завдання: README (умова, критерії, підказки без розв'язку), `solution.py` із заглушкою/наївною реалізацією, `test_solution.py`.
- **Тести мають бути детерміновані:** годинник і джерела недетермінізму передаються параметрами (`clock`, `sleep`, `jitter`, `resolve`), мережі й реальних сервісів немає. Завдання з LLM працюють на мок-LLM (звичайна функція).
- Перед додаванням перевір обидві сторони: заглушка → тести падають; еталонне рішення (пиши окремо, **не клади в репозиторій**, щоб не спойлерити) → тести проходять кілька разів поспіль (гонки й таймінги не флейкають).
- Приклад бага, що вже траплявся: тестовий «не-картковий» номер випадково проходив перевірку Луна. Перевіряй тестові дані обчисленням.
- Кожне нове завдання має РЯДОК У КАТАЛОЗІ з тегом `*CWE:*` (де доречно). Синтаксис тегу: `N` повне покриття, `~N` часткове, `?N` лише згадано в описі, `@N` лише зовнішня лабораторія. Після змін: `python tools/gen_data.py` (оновить сайт, звіт покриття й таблицю в `tasks/README.md`).
- ID завдання на сайті = `t<номер з каталогу>`; папка `tNN_...` підхоплюється генератором автоматично (значок «автоперевірка»).

## AI-проксі

Roman має дешевий проксі `https://api.whitetools.dev` (перевірено): OpenAI-формат `/v1/chat/completions` (з стрімом) і Anthropic-формат `/v1/messages`; embeddings немає. Ім'я моделі лише точно як у `GET /v1/models` (напр. `claude-haiku-4.5`); `response_format` ігнорується, JSON просити в промпті. Усі 🤖-завдання читають `LLM_BASE_URL` (з `/v1`), `LLM_API_KEY`, `LLM_MODEL`; capstone використовує `KA_LLM_*`. Ключ ніколи не комітити (є `.gitignore` на `.env`). CI використовує мок-LLM, а не реальний ключ.
